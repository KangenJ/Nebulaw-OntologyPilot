## Contract and algorithms

- Physical states derive from compiled LATENT dictionaries (up to 64 joint states),
  not legal names or a fixed binary output head. Knowledge markers are excluded.
- One categorical joint transition module and one-output categorical observation
  modules are supported. Other module structures and rules explicitly reject for now.
- All distributions use keyed states/outcomes, exact row coverage and normalized
  finite probabilities. Dependencies outside a module's declared inputs reject.
- Explicit finite contexts cover only reviewed module inputs. No coercion, guessed
  numeric binning, missing-value zero fill, or inferred time intervals.
- Up to the compiled mechanism budget / 256 hypotheses / 16,384 joint belief cells.
  Additional implementation bounds: 64 contexts, 1,000,000 table cells, 8 MiB artifact,
  2,000 accepted event receipts; exceeding these requires explicit new work.
- `initialize({episodeKey, context})`, `advance(belief, {control, context})`,
  `recontextualize(belief, {context})`, `update(belief, event)`,
  `summarize(belief)`, `forecast(belief, plan)` are immutable.
  Context in an advance governs that transition and subsequent observations.
- Computation maintains log P(h,s), with `null` representing exact zero support.
  It never redraws h each step. A zero-likelihood event creates CONFLICTED; downstream
  summaries/forecasts refuse until replay, without a uniform-prior fallback.
- Event shape: `{key, step, variable, kind, value, dependenceKey, verificationMode}`.
  Values distinguish VALUE, UNKNOWN, MISSING and UNOBSERVED. No event has no effect;
  an explicit missing event uses its modeled probability. REVOKED/late events require
  platform replay. GOLD requires a matching compiled policy and physical VALUE;
  NOISY verification uses its declared likelihood, never a hard truth assignment.
- Same key/hash retries are idempotent, including after advancing. New noisy reports
  sharing a dependence key reject conservatively (including across time) until an
  explicit joint observation model exists. Independent GOLD constrains the relevant
  physical state; copies do not multiply another report likelihood.
- INFORMATION_ONLY action transitions must equal WAIT. Forecasts retain shared h and
  never write facts. Scenario predictions are conditional on reviewed assumptions,
  not evidence of a real-world causal effect or completed execution.

## Statistical observation-channel fitting (partial U2 / T04–T06)

`observation-fit.mjs` adds actual sufficient-statistic fitting from frozen native
datasets. It only fits `P(report | same-target-time GOLD state)`. A single verified
outcome per entity does **not** establish a state-transition pair, elapsed-time
contract or intervention response. Initial distributions, transition tables, other
channels and mechanism priors remain explicitly frozen from the reviewed baseline.
Observation modules requiring contexts or additional latent inputs reject until their
supervision is implemented. The current estimator is not neural training.

- `fitObservationModel(compiled, baselineSpec, trainingMaterials, config)` accepts
  current `NativeDatasetRegistry.materialize(..., 'FIT')` output. The private config
  fixes the definition/bridge, target/report variables, classification, collection and
  population policy hashes, approved cohort-protocol hashes, sampling rule, smoothing
  alpha and minimum coverage/counts. Config is an approved-platform dependency, not
  proof of approval merely because it has a hash.
- One qualified target-time report per entity is counted. Missing GOLD stays in the
  original enrolled denominator; no report/UNOBSERVED or multiple target reports are
  explicitly excluded. UNKNOWN and MISSING, if explicitly observed, have their own
  counts. Same sample/entity/event/origin overlap rejects, rather than upweighting
  copied or temporally correlated observations as independent new samples.
- Each row is `(count + alpha) / (row count + K * alpha)`, the symmetric Dirichlet
  posterior predictive mean. Empty rows remain prior-only and are listed explicitly;
  minimum-per-state gates can reject them. This is a **point observation kernel**,
  not a calibrated posterior over observation mechanisms. Existing finite transition
  hypotheses remain reviewed assumptions; they are not fitted by this update.
- Output is an immutable CANDIDATE_UNEVALUATED artifact containing actual counts,
  config, kernel, model/definition hashes, coverage, fitted sample keys and the full
  supplied data/source/feedback provenance. Excluded supplied samples and source refs
  remain in conservative consumption metadata. Input native hashes remain opaque
  native references: the fitter does not pretend it can reconstruct omitted read sets.
- Refit each cumulative union once. The code never adds old counts on top of the same
  data again. Repeating identical inputs returns the same artifact. Dataset additions
  must have disjoint sample/entity/origin identities. Model lineage/version publication
  still needs the native release lifecycle; the fitter does not manufacture a new round.
- `verifyObservationFit(...)` recomputes the complete artifact from authoritative
  frozen data; changing a fitted flag, counts or a self-recomputed hash does not pass.
- `validateObservationModel(...)` checks a distinct VALIDATION cohort against a frozen
  reference, rejects sample/entity/group/source overlap, and reports conditional report
  NLL/Brier plus group-macro NLL. These are **not state-forecast or causal-benefit
  metrics**. A configured NLL regression yields REJECT_REGRESSION, otherwise only
  ELIGIBLE_FOR_REVIEW; neither result authorizes deployment. A baseline with differing
  observation channels across mechanisms is explicitly unsupported by this validator
  until the correct conditional mechanism mixture is implemented.
- FINAL_EVAL is deliberately not accepted here: final-evaluation sealing, native alias
  identity checks at dispatch/result time and actual publication gating are unfinished.
  The native global partition ledger must remain authoritative. In particular, missing
  members' full alias/group identities are not present in this materialized payload;
  native reservations/exposure records must supplement artifact consumption metadata.
  The new native completion method stores their full identity set with the candidate;
  online inference still needs to consume that manifest and deny double-use.
- `fit-once.mjs` performs one bounded (32 MiB maximum input) stdin/stdout fit in a real
  independent process. It has no business credentials or storage and no automatic
  release. The one-job parent below adds bounded supervision and native HTTP transport;
  daemon scheduling and main-service integration remain pending.

## Private FIT worker and real HTTP transport

`runObservationFitJob` claims one explicitly assigned native FIT job, uses only the
returned approved recipe and input, then submits its actual artifact for independent
platform recomputation. `worker-once.mjs` is its CLI entrypoint. The worker parent holds
the current private token; the fixed `fit-once.mjs` child receives neither that token nor
the parent's environment/Node options. Child code has no native storage/API client.

Default limits: 30-second child wall time, 256 MiB V8 old-space limit, 32 MiB input,
9 MiB stdout, 64 KiB discarded stderr, 180-second HTTP timeout, and 30 seconds reserved
from the remaining lease for completion. Old-space is not a total RSS bound or an OS
sandbox. The child is killed on timeout/output overflow and awaited through close.
Unsupported model structure fails explicitly; it never falls back to an old checkpoint.

The server URL is a configured literal loopback HTTP origin, with no URL credentials,
path/query or redirect. Every request rereads the private token. A claim with insufficient
lease budget is left for native lease recovery; it is not fabricated as a successful fit.
A known child failure reports only FIT_PROCESS_FAILED against the current lease.
After submitting completion, ambiguous transport failure causes one identical retry;
it never reclaims, recomputes or marks a possibly successful job FAILED. If both replies
are unavailable it returns FIT_COMPLETION_UNCONFIRMED; inspect the native job/receipt
before taking further action. No artifacts or lease credentials are printed by the CLI.

## Polling native jobs, exhausted cleanup and process recovery

`drainObservationFits(options)` obtains bounded worker-scoped native discovery, validates
the returned summary contract and processes up to `maxJobs` (default 1, maximum 20).
CLAIM goes through the existing real fit path; RECONCILE_EXHAUSTED uses the separate
versioned cleanup command. There is no arbitrary task payload or caller-selected code.
Result items report attempt outcomes, not invented native statuses: ERROR can mean a
known failure, a race, or an uncertain outcome; inspect the native job when needed.
Ambiguous transport/completion, revoked credentials or forbidden operations stop the
batch without guessing success, marking possibly successful jobs failed or claiming a
replacement lease. Later cycles rediscover actual current native state.

`startObservationFitWorker` runs one cycle at a time and waits 5 seconds by default
between completed cycles (configured interval 1–300 seconds). `close()` prevents another
job/cycle and awaits the current bounded operation; it does not cancel business work.
The daemon CLI handles SIGINT/SIGTERM this way. Forced termination leaves native leases
to expire and be recovered. Computation may repeat after lease recovery; successful
native result submission remains idempotent. This is not an exactly-once computation
claim, nor a total process/OS isolation guarantee.

With an already configured private listener and worker discovery grant:

```sh
# PLUS_COMPUTE_URL and PLUS_WORKER_TOKEN_FILE are the same private settings as above.
export PLUS_WORKER_INTERVAL_MS=5000
node --max-old-space-size=256 services/plus-engine/worker-daemon.mjs
```

No execution ID is needed: the platform selects the worker's eligible pending/expired
jobs. The daemon processes one job per cycle by default and prints sanitized state and
receipt IDs, never training inputs, labels or lease/credential values. FAILED/DEGRADED
cycles expose codes, and a failed cycle clears the prior result rather than showing it
as new success. Deployment/service registration, current-account/Task policy assembly,
resource monitoring and end-user UI integration remain unimplemented.

Recovery tests terminate an actual one-job CLI after the native lease has committed but
before data delivery, then advance a controlled lease clock, reopen native storage and
run a fresh polling worker. The replacement discovers, reclaims, computes and commits
one candidate; both authorized exposures remain and the old lease cannot write. This
is real process termination/native recovery with a controlled expiry clock, not a
claim that five wall-clock minutes or a production host outage were tested. A separate
transport-only fixture runs the actual daemon CLI for two nonoverlapping idle cycles
and verifies graceful termination; it is not evidence of native model approval.

## Actual state-estimation validation

`state-evaluation-protocol.mjs` registers `finite-state-estimation-validation-v1`.
Its prospective configuration fixes STATE_ESTIMATION, minimumSamples,
minimumCoverage, maximumNllRegression, maximumBrierRegression and a validated
fixed-step clock tied to the definition/binding. The clock is an evaluation contract,
not approval of a live deployment. There is no default inferred clock or rounding.

The adapter revalidates the actual fitted observation candidate and held-out native
material, then runs `runFiniteTimeline` independently for baseline and candidate.
Only matching authorized temporal inputs enter those predictions; later GOLD enters
the scorer, not inference. Snapshot, event, time, binding and content hashes must
agree. Source/entity/group overlap, missing/substituted history, off-grid time and
zero supported GOLD probability refuse evaluation instead of fabricating metrics.

Metrics include state NLL/Brier, group-macro candidate deltas, a fixed descriptive
confidence histogram/ECE and prediction-receipt hashes. Either frozen regression
gate can reject the candidate. Bins are not a calibration certification. The declared
population remains one prospectively enrolled target report per entity; this is not
an assessment of all missing-report processes. Same-past predictions remain unchanged
when only isolated scorer truth changes, as tested with explicit synthetic fixtures.

This scores the observation kernel's contribution to current-state inference;
initial/transition priors remain reviewed assumptions. Future forecasting, learned
transitions, causal benefit, neural candidates, sealed final evaluation and real
business benefit are explicitly outside this result. No result authorizes deployment.

## Non-Transformer U3 observation-channel candidate

`neural-observation-fit.mjs` adds `ontology-categorical-tanh-channel-v1`:
the published compiled latent-state dictionary supplies one-hot inputs; one tanh
hidden layer produces softmax probabilities over the compiled typed report
dictionary. Category order is canonical, and VALUE, UNKNOWN and MISSING remain
different outputs. UNOBSERVED is excluded by the existing supervision contract.
Neither legal variable names, prior experiment weights nor Transformer layers
are used. Parameter count is H(K+1)+C(H+1), not a fixed experiment dimension.

The config is `{schema:'plus-neural-observation-config-v1', supervision, network}`.
Supervision reuses the U2 `plus-observation-fit-config-v1` contract. Network freezes
schema=`one-hot-tanh-softmax-v1`, hiddenWidth (1–32), epochs (1–2000), learningRate,
l2 and seed. A bounded deterministic full-batch gradient descent trains the final
fixed epoch; heldout data cannot select epochs, seeds or gradients. Supervision's
smoothingAlpha belongs to the same-information statistical control, not neural
gradient updates. U3 requires qualified labels covering every target state, since
shared weights could otherwise alter unlabelled state rows. Compute/support
limits reject oversized work before training, not by silently truncating data.

This is a POINT observation kernel, not a learned mechanism posterior. Initial
distributions, transitions and reviewed mechanism priors remain frozen. GOLD is
a training-only channel covariate: the finite online filter enumerates possible
states and consumes a report, never the target's later GOLD label. Fitted weights,
the exact untrained weights/kernel, ontology layout, hashes, source consumption,
training loss and missingness/coverage are recorded in an immutable candidate.
The artifact itself always reports predictionReady=false and no publication right.

Pure channel validation compares configured no-update reference, same-information
U2 and exact untrained control on the same qualified holdout. A regression against
any frozen NLL gate rejects the candidate. Conditional report scoring is NOT state
prediction quality; current published-model comparison, native state evaluation,
sealed final evaluation and business benefits remain separate outstanding gates.

`native-neural-fit-verifier.mjs` provides an explicit adapter to the EXISTING
NativeRecipeRegistry/NativeComputeAdmission. The recipe keeps shared purpose and
binding fields in config and adds immutable network capacity; approval is native.
The verifier reloads current approved content before/after actual recomputation.
`neural-fit-once.mjs` is a fixed pure child with strict bounded JSON input, no
database/credential handling and no publication authority. Its verified output
can persist as a native U3 CANDIDATE with recipe/dataset/exposure/source links;
idempotent reopen and source/recipe withdrawal use existing native governance.

Tests cover independent central-difference gradients for every parameter, actual
two-batch cumulative fitting, contamination/refusal, regression, tampered weights,
real child-to-native candidate completion and withdrawal. Native integration uses
explicit SYNTHETIC Machine source transactions and controlled historical time,
not canonical Task or private-host U3 admission. The current Task private engine
allowlist remains U2-only: this addition does NOT enable U3 in its HTTP worker,
state evaluator, online selection or deployment. Multi-dataset native dispatch,
two complete native U2/U3 update/evaluation rounds and clean rollback remain due.
